## 3. Core type vocabulary

1. Harness — `interface Harness extends Session` (`dist/harness/types.d.ts:918`); value is const
   `Harness` with `open(storage, options, context)` (`dist/harness/harness.d.ts:21`). Owns
   scheduling (`resume()`, `wake()`), conversation/task/submission handles, signals, observers.
2. Session — the commit/close/watch layer below the Harness (`commit()`, `watchDoc()`,
   `observeCommits()`, `closed`), from `createSession` (`dist/session/session.d.ts`).
3. Conversation — stateless handle (`dist/harness/types.d.ts:851`): `submit`, `admit`, `compact`,
   `reset`, `fork`, `abort`, `context`, `entries`, `watch`.
4. Entry — immutable transcript record, `kind` + `is()` guard (`dist/types.d.ts:480`, `:446`);
   built-ins in `dist/entries.d.ts`: Assistant, User, ToolResult, System, Compaction, Reset.
5. Document — `defineDoc`/`defineDocFamily` (`dist/documents.d.ts`), `DocToken`
   (`dist/types.d.ts:81`), persisted as `DocumentRecord` (`:735`).
6. Task — `interface Task<I,S,R,H>` (`dist/types.d.ts:355`) over `TaskDefinition` (`:330`):
   name, version, `initial`, exhaustive `phases`, required `abort`, optional `migrate`.
7. Submission — `interface Submission` (`dist/harness/types.d.ts:86`): `status`, `wait`, `abort`.
8. Extension — named bundle of tools, prompt sections, hooks, wraps, tasks, code-mode
   namespace (`dist/harness/types.d.ts:436`).
9. Registry — hot-swappable extension set: `install`/`uninstall` (`:476`), `snapshot()`/
   `subscribe()` (`:469`), immutable `RegistrySnapshot` (`:452`).
10. Agent — resolved per-conversation configuration (`dist/harness/types.d.ts:548`); stored as
    names in `pi.agent`, resolved against the registry at each use.

  `/delta` (41), `/sqlite` (27), `/watch` (15), `/output` (12), `/sqlite/node` (6),
  `/sqlite/cloudflare` (6). Symbols: store/commit vocabulary (`Step`, `StagedWrite`,
  `SeriesCommit`, `Store`, `OwnerTable`), document identity, `Op` from `/delta`,
  `WatchHandle`/`WatchCall`/`WatchEnd`/`NativeWatchCall` from `/watch` (re-exported from
  `dist/index.d.ts:1`), `Context`.
- **chord ships `./http`, `./app`, `./web`, `./tui`, `./workers`, `./plugins`, `./react`,
  `./sync`, `./surfaces`, `./compression`, `./telemetry-ingest` — pi-durable imports none of
  them.** `dist/` has no `node:http` or `createServer` reference.
- Absent with two-way proof (not in `dependencies`; zero import specifiers in `dist/`):
  `pi-agent-core`, `pi-coding-agent`, `pi-tui`, `pi-web-ui`, `pi-protocol`, `pi-client`.
- Inference: pi-durable is a **peer of pi-agent-core**, not a layer on it. It reimplements the
  agent loop over pi-ai + chord and brings its own tools, env contract, image pipeline, and
  storage contract. A host must supply storage, an `ExecutionEnv`, providers, transport, UI.
