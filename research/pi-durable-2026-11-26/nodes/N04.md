## 1. The watch call shape

`Conversation.watch(context, window?)` → `ConversationWatch = WatchHandle<ConversationView>`
(`dist/harness/types.d.ts:905-916`). `WatchCall` comes from chord (`dist/index.d.ts:1`):

```ts
export type WatchCall<T> =
  | { readonly kind: "value"; readonly value: T; readonly ops: readonly Op[]; readonly retired: boolean }
  | { readonly kind: "failed"; readonly error: unknown };
```

- Durable never sends `failed`; its failures end the watch (README:583).
- The listener signature is `start(listener: (call, context) => Promise<void>)` — the `Context`
  is the second argument, never part of the call.
- `retired` is hardcoded `false` for views (`dist/harness/view.js:241`); a reincarnated
  document arrives as `["s", ["docs", kind], value]`.
- `WatchEnd` = `{kind:"stopped"|"aborted"|"ended"}` | `{kind:"listener_error", error}` |
  `{kind:"failed", error}`. On close a watch ends `ended`; a synchronous observer ends
  `failed` with `new Error("session closed")` (`dist/session/session.js:1518-1528`).

## 2. `ConversationView` — every field

| Field | Meaning |
|---|---|
| `conversation` | id, optional `parent {conversationId, at}` (fork source), optional `owner {conversationId, taskId}` |
| `entries` | window over the fork-aware transcript in ID order; head markers (compaction summary, reset, handoff) in place |
| `before?` | ID of the entry just before the window; absent when the window starts the transcript |
| `docs` | built-in documents by kind: `pi.agent`, `pi.live`, `pi.inbox`, `pi.provider`, `pi.usage`; third-party documents are not mounted |

`EntryRecord`: `id`, `conversationId`, `kind`, `model?`, `data?`, `head?`, `edits?`,
`byTaskId?`.

`docs["pi.live"]` = `LiveState` (v3 in 1.6.1, `dist/harness/live.js:5`):

| Field | Meaning |
|---|---|
| `run?` | present exactly while busy: `{taskId, inputs, turns, first?, afterRun?, yield?}` |
| `generation?` | `{attempt, message?, retry?, deferred?}` — committed throttled partial of the streamed answer, durable backoff `{at, error}`, deferred poll `{pollAt}` |
| `tools?` | current round in call order: `callId`, `name`, `status: pending\|running\|sleeping\|waiting\|done`, `output`, `droppedBytes`, `droppedLines`, `details`, `diagnostics`, `taskId?`, `unoffered?`, `entry?` (absent after a fault) |
| `nestedTools?` | calls a tool made via `executeTool()`: adds `parentCallId`, `parentTaskId`, `arguments`, `summary {isError, durationMs, usage?, error?}` |
| `compactions?` | live compaction tasks: `taskId`, `trigger manual\|threshold\|overflow`, `blocking`, `attempt`, `retry?` |
| `compactionFailure?` | newest compaction failure, kept until a summary is produced |
| `runFailure?` | newest run without an answer: `taskId`, `inputs`, `reason` (10 values incl. `model_error`, `interrupted`, `restart_limit`, `turn_limit`), `detail?`, `first?` |

`ConversationWindow`: `{from?, min=50, max=2*min}`; bad bounds throw `RangeError`.

## 3. The ops that travel with each value

Chord `Op`: `["r", value]` replace root, `["s", path, value]` set, `["d", path]` delete,
`["a", path, text]` append, `["t", path, n]` keep `slice(n)`, `["p", path, start, del,
items]` splice, `["m", path, perm]` reorder. A `WireOp` form adds path interning for the wire,
produced only by `encoder()`/`decode()`.

View ops are re-prefixed: a document op `["s", ["generation","message"], v]` becomes
`["s", ["docs","pi.live","generation","message"], v]`. A doc-delta root `r` becomes
`["s", prefix, value]`, so a view's root is never replaced by a document. Window overflow
emits three ops: insert, splice-remove, `["s", ["before"], id]`.

Coalescing: commits that land while a listener runs arrive in one callback with the newest
value and folded ops ("appends to one string join, sets of one field keep the last").
Past `MAX_PENDING_OPS = 10000` the callback gets one root replacement `[["r", view]]`, holding
at most `max` entries. Window: newest 50, append, and past 100 the oldest leave in one splice
down to 50.

## 4. `ConversationTranscript` — what is already solved

- `merge(view)` returns `Omit<ConversationView,"entries"|"before"> & {items}`; a merge that
  adds nothing returns the same array. Items: `{kind:"entry", entry}`, `{kind:"gap", after,
  upTo}`, `{kind:"earlier"}`.
- `resume` getter → `{from: newest + 1}`, `{}` when empty, `undefined` before first merge;
  feeds `watch(context, transcript.resume)`.
- `loadEarlier()` pages before the oldest held; `fillGap(gap)` pages a gap; concurrent calls
  for one page share one load. Gap detection uses `before` vs what the client holds.
- Solves transcript continuity, pagination and stable item identity. Does not solve turns,
  tool cards, streaming presentation, or transport.

## 5. Sync observers and their timing

`observeConversation(id, observer, context, window?)`, `observeTaskGraph`, `Session.observeDoc`,
`Session.observeCommits`.

- `advance(call, context)` is always a `value` call. Spec §9.1: "advance runs inside the
  storage's commit, so an observer records the change and returns: no awaits, no Session
  calls, no throws, and quick, as its time is part of every commit."
- Timing: watchers/observers see a deferred commit when memory adopts it, **before storage**
  (up to `settings.progress.persistWithinMs`, default 1000 ms). `observeCommits` runs one
  microtask after publication, with exactly what was stored.
- Ends: `ended` at close, `failed` with "session closed" or the Session error,
  `listener_error` on a throw (which detaches).

## 6. The removed event stream

Removed in 1.5.0: `watchEvents()`, `AgentEvent`, `AgentEventStream`, `SnapshotEvent`,
`MessageChange`, `ToolEventCall`, spec §9.4 (CHANGELOG:124, issue #11327). Zero hits for those
names in 1.6.1 `dist/` or README — the removal is complete.

Reason (CHANGELOG:124): "A renderer renders state instead of assembling it from events:
everything the events carried that a renderer draws is in the conversation view, typed for
producer and consumer, and new information becomes a field there rather than an event type
every client must learn."

Migration table maps every old event to a state field (`snapshot`, `run_start/end`,
`turn_start/end`, `message_update`, `tool_execution_*`, `auto_retry_*`, `deferred_poll`,
`compaction_*`, `inbox_update`, `agent_changed`, `usage_changed`, `submission`, `task_failed`,
`run_end` unanswered).

**Data with no state home** (CHANGELOG:185) — the real loss:
1. A tool's arguments after repair and `beforeTool` at its start, for a model-issued call —
   only in the tool task's checkpoint.
2. A submission's settlement — only `Submission.status()/wait()` and `Harness.submission(id)`;
   an input settled without a run just leaves `pi.inbox`.
3. A failed task's error — only `Harness.getTask()` and `onReport`.
4. A nested call's full result — only the caller's `NestedCallDoc`, which retires.
5. Exact turn boundaries — only inferred from `run.taskId` and the task graph.
6. Whether a compaction did anything — only `CompactionResult` and the summary entry.

## 7. Channel inventory

| Channel | Payload | Timing | JSON-safe |
|---|---|---|---|
| `Conversation.watch` | `WatchCall<ConversationView>` | attach, then each commit | yes (Context arg is not) |
| `Harness.watchTaskGraph` | `WatchCall<TaskGraph>` (state `pending/running/waiting/sleeping/completing`, `blocked?`) | same, plus commit-less advances | yes |
| `Session.watchDoc` | `WatchCall<T>` per change, `retired: true` | same | yes |
| `observe*` | same, unfolded, via `advance` | inside the storage commit | yes |
| `observeCommits` | `CommitPublication {seq, changes}` | one microtask after publication | yes |
| `onReport` | `Report` = `ReportInfo` + `error: unknown` | failure time only | **no** |
| telemetry | spans `pi.durable.submit`/`.phase`; events `.entry`/`.submission`/`.report`/`.checkpoint`/`.replay`; metrics `.reports`/`.phase.duration`/`.tasks.active` | admission, phase, each report | yes, content-free |
| `getTask`/`waitForTask` | checkpoint, memos, `restarts`, outcome | pull | yes |
| `snapshot`/`snapshotAsOf` | any document, incl. third-party and historical | pull | yes |
| `entries` | `Page<EntryRecord, Cursor>` | pull | yes |
| `context` | `ContextView` — active transcript, model messages | pull | yes |
| `inspect` | scheduler state, `TaskInspection[]`, `SubmissionRecord[]` | pull | yes |
| `closed`/`onWake` | `SessionEnd`, `{active}\|{at}\|{}` | close, commit | error is not |

What each adds over a watch: terminal task outcomes and checkpoints, third-party documents,
history beyond the window, the exact model messages, unsettled submissions, errors that are
never state, and cross-process phase facts.

## 8. Serialization

Views, ops, entries and publications are plain JSON trees. Records pass `copyJson(...)` on
write; timestamps are epoch-ms numbers; branded IDs are compile-time only. Caveats:
immutability is a contract, not enforcement; values are structurally shared across observers,
so a fan-out must copy or serialize at the boundary; `WatchEnd.error`, `Report.error` and
`SessionEnd.error` are not JSON; `Context` is deliberately outside the call.

## 9. What `apps/p2` actually does (correction to the orchestrator's steer)

`apps/p2/src/runtime/observe.ts` is a file-watch helper; `runtime/durable.ts` is registry
composition. Neither carries the view. The real consumer is `apps/p2/plugins/chat/`
(`worker.ts` 589 lines, `contract.ts` 357, `web.tsx` 2,104, `tui.ts` 1,220).

The host subscribes with the synchronous observer, derives a chord `Watchable`, derives a
host-shaped value (image parts replaced by `ImageRef`s so bytes stay on the worker), and
publishes that as a chord member. `ViewSchema = unsafe<ConversationView | null>(unknown())`.
**Durable's `ops` are dropped at the first derive**; chord replicates the derived member with
its own ops. The only use of Durable ops is a continuity hint
(`apps/p2/src/web/history.ts:194-198`): a lone `["r"]` means "whole value, not a delta".

## 10. What a renderer still does itself

1. Transport and tenancy: no server, no client, no protocol; p2 uses chord contracts, its own
   `Chat.entries` pagination, auth variants, and per-client redaction of inline base64 images.
2. Ops application, if kept: chord has `apply`/`encoder`, but no client replica.
3. Turn assembly: view is a flat entry window plus flat slots. p2 needs 802 lines
   (`src/web/activity/model.ts`) + 581 lines (`src/web/transcript.ts`) to join calls to slots
   and result entries, plus 2,104 lines of web renderers and 1,220 of TUI renderers.
4. Status derivation: `sleeping`/`waiting` shown as running, `done` without `entry` means
   faulted, `unoffered` needs copy, nested trees rebuilt from `parentCallId`.
5. Numbers the view does not carry: context size and latest usage (p2 recomputes in
   `conversation-stats.ts`), per-response cost.
6. Gap and resume UX, device-cache seeding, divergence detection (~230 lines `history.ts`).
7. Failure copy for 10 `runFailure` reasons plus retry/deferred policy.
8. Audit history: by design absent.
