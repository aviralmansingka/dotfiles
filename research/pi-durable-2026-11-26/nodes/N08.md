# N08 brief — Verdict on H1

Child: n08-verdict-durable. State: done. Input: briefs N01-N07 and the lessons.

## 1. Verdict

**PARTLY SUPPORTED.** Defensible wording:

> For a local single-user host, pi-durable 1.6.1 already hands over a complete, typed,
> JSON-safe committed state plus a transcript merge helper, and no first-party renderer for
> 1.6.x exists — that much of the claim holds. But what a host displays is committed state, not
> events (1.5.0 removed the event API), and a renderer is one of at least five independent gaps:
> transport, user identity, a 1.6.1-clean SQL backend, and backup/delete all survive a complete
> UI.

## 2. Sub-claims

| Sub-claim | Verdict | Strongest evidence |
|---|---|---|
| H1a: a UI for a host to display progress is missing | Supported, and understated | "No first-party renderer for pi-durable 1.6.x exists as a package"; the only one, p2, is `private: true` and its README says "It will be gone soon… Do not build on it" (N06 §1, §8). What is missing is components **and** transport (N05 §8) |
| H1b: the thing displayed is `events` | **Refuted** | 1.5.0 removed `watchEvents()`, `AgentEvent`, `AgentEventStream`, `SnapshotEvent`, `MessageChange`, `ToolEventCall`; spec §9.3 "A renderer renders the newest value; it never assembles state from a stream of events" (N04 §6, CHANGELOG:124) |
| H1c: the UI is the only thing missing | **Refuted**, true only for a local single-user app | A hosted app keeps four blockers that a UI cannot fix: transport, user identity, a compliant SQL backend, backup plus deletion (N07). UI ranks 10th of 16; nine rank above it |
| H1d: missing work, not deliberate layering | Partly | Deliberate: no event journal, one writer per storage, no CRDT or exactly-once (CHANGELOG:124, spec §9.4, §13). Inference only: transport fits the layering but no vendor statement says so (N07). No design excuse: no backup/delete/export, no 1.6.1-clean adapter, no IndexedDB upgrade branch, stale launch post |

## 3. Steelman

From the runtime author's chair, the package already gives a renderer everything.
`ConversationView` holds the conversation record, an `entries` window with `before`, and five
documents. `pi.live` alone carries the run, the throttled partial with usage, retry backoff,
deferred poll, one slot per tool call with status/output/details/result, nested calls with
`parentCallId`, compactions, `compactionFailure`, and `runFailure` with ten reasons. Chord ops
arrive per commit, `ConversationTranscript` gives merge, load-earlier, gap fill and resume, and
the whole value is plain JSON. The README states the contract: "Everything a UI needs is
committed state." `apps/p2` is an existence proof at exactly 1.6.1. N07 concedes the local case:
"Nothing blocks it… friction, not blockers." From inside the runtime, the state is finished and
only pixels are pending.

## 4. Rebuttal

- "Just draw it" is about 4,700 lines in first-party hands: 802 lines of activity model, 581
  lines of transcript display model, 2,104 lines of web renderers, 1,220 of TUI (N04 §10, N06
  §1). The vendor that wrote it says do not build on it, and its successor is headless.
- Three incompatible wire framings were invented independently: raw chord ops over a WebSocket
  with `applyImmutable`; HTTP plus SSE with a `?known=<version>` token; coalesced view changes
  every 90 ms over SSE; plus one more SSE (N05 §7). Two hosts re-derived the same seam by hand.
- Zero storage adapters pass the 1.6.1 contract (N03 §5), so a hosted store is one SQLite file
  on one process with one writer and no lock (N07).
- There is no user identity at all: `principal`, `tenant`, and `audit` return zero hits, and
  `signal()` checks no sender (N07). "Who may steer" is an undecided question, not a rendering
  one.
- The view cannot carry six facts a renderer wants (repaired tool arguments, submission
  settlement, failed-task error, nested full result, exact turn boundaries, whether a compaction
  changed anything). Reading them needs `getTask`, `submission()`, and `onReport` (N04 §6).
- Adoption: no observed public app runs 1.6.1 five days after release, and the flagship example
  is on 1.5.2 (N07). The word "events" most plausibly comes from the 1.0 launch post, which still
  teaches `viewState()`, `documentState()`, and `watchEvents()`.

## 5. What would move the verdict to SUPPORTED

1. A published first-party renderer on 1.6.x, or p2 published and no longer disclaimed. That
   would show the display model is transferable rather than app-local.
2. One documented wire contract with two independent consumers: a `./wire` or `./client` export,
   or a shipped recipe that exercises chord's `createHttp` plus links path.
3. A third-party SQL backend that passes the 33-case conformance suite at 1.6.1, plus
   conversation deletion, export, and any `principal` concept.

## 6. Confidence

High. H1b and H1c rest on two-way absence checks against shipped code, CHANGELOG lines, npm
metadata, and nine public repositories, and the ranking holds across six independent briefs. The
only soft edge is H1d's classification of transport as deliberate layering, which N07 flags as
inference.
