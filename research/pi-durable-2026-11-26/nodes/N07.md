## If a complete UI existed tomorrow

**(i) Local single-user app.** Nothing blocks it. Four things bite in order: the stale launch
post and unshipped examples; a breaking change on the first `npm update`; a renamed extension
stranding a task live forever; a second chord copy if the app already uses chord. SQLite storage
and the Node environment are enough. **Verdict: friction, not blockers.**

**(ii) Hosted multi-user web app.** Four blockers, and a UI fixes none of them. No transport and
no command-authorization model; no user identity anywhere in the package, so "who may steer" is
the host's layer; no SQL backend that passes the 1.6.1 contract, so the store is one SQLite file
on one process, with one writer and no lock; no backup and no delete, which fails an ops review
and a data-deletion review together.

**(iii) Serverless deployment.** The execution environment is the wall. Only `NodeExecutionEnv`
exists, so tools return error results in a Worker until someone implements 27 members; there is
no D1 adapter; a missing alarm silently strands every sleeping task; and a remote client still
needs the transport. The durable model was built for this host, and the adapters were not.

## Deliberate design versus missing work

**Deliberate, so not gaps:** no event journal (CHANGELOG:124, spec §9.4); no CRDT or offline
multi-writer, no whole-Session DOM, no automatic checkpoint heuristic, no JSONL compaction (spec
§13); no exactly-once side effects; one writer per storage (README:1051 states it).

**Deliberate-looking, but only as inference:** transport absence fits the layering (chord ships
`http`/`links`/`app`, and pi-durable imports none), but no vendor statement says so. The same
holds for auth, which a sibling provides.

**Missing work, with no design excuse:** the stale launch post and no post since 2026-10-16; the
dangling TOC entry; examples outside the artifact; no backup or export in a package about durable
state; no deletion; usage recorded but never capped; an `upgradeneeded` with no upgrade branch;
two doc statements that contradict the code; an adapter contract nobody has satisfied at the
current version; no app on 1.6.1 five days after release, and a 1.5.2 flagship example three
weeks stale.

## Limits

- The Cloudflare example's current pin comes from N06, not a fresh check.
- "Copy the file" as a SQLite backup is the researcher's inference; the package says nothing.
- Serverless conclusions rest on absent adapters, not on a failed run.
- The duplicate-chord-copy problem (D3) is mechanism reasoning; the conflicting install was not
  constructed.
- Severity is judged for a serious host. A hobby local app downgrades most of the table.
