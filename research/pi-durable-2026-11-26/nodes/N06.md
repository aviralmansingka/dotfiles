# N06 brief — UI surfaces that exist today

Child: n06-ui-surfaces-durable. State: done. Evidence: monorepo `apps/p2`, `apps/p3` and the
archived UI sketch; npm metadata and tarballs for `pi-web-ui@0.75.3`, `pi-tui@1.6.1`,

## 1. The correction: p2 is the first-party renderer

- `apps/p2/package.json`: `"name": "p2"`, `"version": "0.0.3"`, **`"private": true`**; deps
  `pi-durable 1.6.1`, `chord 1.6.1`, `pi-tui 1.6.1`, `pi-ai 1.6.1`, `react 19.3.0`,
  `react-dom`, `ws 8.21.0`, `discord.js 14.28.1`, `elanor-react 0.1.0` + design tokens,
  `marked`, `grok-mermaid`, `lowlight`. Scripts `start` → `src/hosts/server.ts`,
  `tui` → `src/hosts/tui.ts`. `npm view @earendil-works/p2` → 404.
- Last commit touching `apps/p2`: `2e4deff6`, 2026-11-25T13:18:50Z, right after "Release
  v1.6.1".
- Its README disclaims it: "> [!WARNING] # EXPERIMENTAL — **p2 is a prototype. It will be gone
  soon.** It is not supported, its data formats and APIs change without notice, and it will be
  replaced. Do not build on it or run it for anything you depend on." Then: "A self-hosted Pi
  Durable UI built from independent Chord plugins."
- Size: 1,263 files under `apps/p2`. `src/web/` = 88 files, 632 KB, 35 `.tsx` (`Chat.tsx`
  30.4 KB, `transcript.ts` 23.2 KB, `use-chat-scroll.ts` 37.9 KB, `activity/model.ts` 34.1 KB,
  `style.css` 79.6 KB). `src/tui/` = 35 files (`components/transcript.ts` 18.8 KB,
  `messages.ts`, `tool-execution.ts`). Hosts `src/hosts/{server,tui,web}.ts`, plus a Discord
  host.
- It draws durable state directly. `src/web/history.ts:1`: "A viewed conversation's transcript
  on a client (web and TUI): Durable's `ConversationTranscript` over the window the
  conversation's `Chat.view` holds." It imports `ConversationTranscript, ConversationView,
  EntryId, TranscriptItem, TranscriptView` from pi-durable and `Watchable/WatchEnd` from
  chord/watch. `src/web/transcript.ts:1`: "Pure display model of a Durable view: tool calls are
  joined with their live slot and result entry"; it imports `AgentState, EntryRecord,
  InboxState, LiveState, NestedToolSlot, ToolSlot, TranscriptItem, TranscriptView`.
  `src/runtime/tui-renderers.ts` types `TuiEntryRenderer = (entry: EntryRecord, ctx) =>
  Component | undefined`.
- Reusable as a package: no. It is private, unpublished, and its browser API is an in-repo
  facet export (`src/api/v1/web.ts`).
- Warning for readers: p2's docs use "views" for panes (`docs/views.md`), a different sense
  from pi-durable's `ConversationView`.

## 4. Buckets

- **(i) Library that renders durable views: exactly one, third-party.**
  `@usecontextlayer/pi-durable-assistant-ui@2.2.0`: peer `pi-durable ^1.5.0`, deps pinned
  `chord 1.5.0` and `pi-ai 1.5.0`. Exports `createHttpPiDurableClient`, `usePiDurableRuntime`,
  `PiDurableConversation`, `projectConversation`, attachment and thread-list adapters, and
  re-exports `ConversationView`, `TranscriptView`, `EntryRecord`, `AgentState`, `InboxState`.
  It is an adapter, not components: the pixels come from `@assistant-ui/react`. Its own
  command "pins Pi Durable to the verified 1.5.0 release"; nothing shows a 1.6.1 test.
- **(ii) Apps that render with their own code**: 9 of 11 dependents plus one inspector. Three
  patterns: raw view + chord ops (pi-durable-cloudflare, ultimate); view on the server with a
  proprietary projection (pi-pocket, xiaomoBoy, disler); committed storage or journal read back
  (durable-lens, vercel `pi-view`). None ships a reusable component.
- **(iii) A UI for a different pi runtime**: `pi-web-ui`, pi-coding-agent's TUI, `companion`,
  vercel `harness-pi`, `dpi-tui`.
- **(iv) Private first-party app**: `apps/p2` at 1.6.1.
- Dead reference: p2's `src/tui/components/transcript.ts` cites "coding-agent's DurableTui
  (experimental/durable/tui.ts)". That path does not exist on `main`, and no published
  DurableTui exists.

## 5. pi-web-ui, the real facts

- dist-tags: `latest 0.75.3`, `legacy-node20 0.74.2`. Versions are only 0.74.0-0.74.2 and
  0.75.0-0.75.3. **One major line (0); no 1.x ever.**
- Created 2026-05-07; 0.75.3 published 2026-05-18T09:59Z; `time.modified` 2026-05-27 is
  registry metadata. **No code change since 2026-05-18.**
- No `repository`, `homepage`, or `bugs` field. It does not point at the pi monorepo, and it is
  not a package on `main`.
- deps `pi-ai ^0.75.3`, `pi-tui ^0.75.3`, pdfjs, xlsx, jszip, docx-preview, ollama, lmstudio,
  lucide, typebox; peers `lit ^3.3.1`, `@mariozechner/mini-lit ^0.2.0`. **`pi-agent-core` is
  not declared** — it is imported type-only and is a phantom peer.
- It speaks `AgentEvent` exclusively: `AgentInterface.connectedCallback` does
  `this.session.subscribe(async (ev: AgentEvent) => …)` over `turn_start`, `agent_start`,
  `message_end`, `message_update` (`src/components/AgentInterface.ts:153-179`).
- It cannot be pointed at a `ConversationView` without an adapter:
  1. Shape: the view has `{conversation, entries, before?, docs}`, no `messages`, no `state`,
     no `subscribe`. Head markers and forks are structure it cannot show.
  2. Events vs state: 1.6.1 removed the event API that pi-web-ui subscribes to.
  3. Version skew: pi-web-ui compiles against pi-ai 0.75.3; 1.6 changed `Message`, added
     `thinkingLevel`, `deferred`, `durationMs`, `endTurn`, `rawStopReason`. It also augments
     `CustomAgentMessages` on a package it does not depend on.

## 6. pi-tui and the coding agent

- `pi-tui 1.6.1` ships widgets and terminal plumbing (Box, Text, Markdown, Editor, SelectList,
  ScrollView, Image, keybindings, `StdinBuffer`), **no conversation renderer and no message
  types**. A host reuses widgets; nothing renders a transcript.
- `pi-coding-agent 1.6.x` does export a chat renderer: `AssistantMessageComponent`,
  `UserMessageComponent`, `ToolExecutionComponent`, `createChatViewport`, `EntryRenderer`,
  `MessageRenderer`. Its inputs are pi-ai messages and its own `SessionEntry` union, not
  `EntryRecord`. It declares no pi-durable dependency.

## 7. Third-party leads

- `@usecontextlayer/pi-durable-assistant-ui@2.2.0`: four versions, all 2026-11-08. It documents
  runtime limits it works around: "Pi Durable 1.5.0 has no native queue move/edit, permanent
  conversation deletion, archive or unarchive operation."
- `durable-lens@0.1.0`: "A local, read-only inspector for pi-durable storage"; CLI plus local
  page; reimplements the store readers, zero runtime deps. Its supported list stops at 1.4.0
  ("written by pi-durable 1.2.0, 1.3.0, 1.4.0 and the unreleased main branch"); README claims
  "1.4 or later", so 1.5 and 1.6 are unverified.
- `@earendil-works/elanor-react@0.1.1`: 66 generic Base UI components; a grep for
  chat/transcript/message/conversation/markdown matches only `tooltip`. It has building blocks
  (`prose`, `code-snippet`, `collapsible`, `file-tree`) and nothing for a transcript or a tool
  call.

## 8. Documentation of the intended UI path

- The pi-durable README has no UI, renderer, web client, or example-app section. The only
  UI-adjacent line is the contract "Everything a UI needs is committed state".
- The CHANGELOG has one renderer statement: the removal rationale.
- npm scope check: `pi-view`, `pi-web`, `pi-ui`, `pi-chat`, `pi-web-ui-2`, `p2`, `react-ui`,
  `components` all return 404 under `@earendil-works`.
- `packages/` has no web/ui/view/client package.

**Answer: no first-party renderer for pi-durable 1.6.x exists as a package.** One exists as
unsupported private source (p2), with a first-party example app on 1.5.2 beside it, and the
declared successor (p3) has no page.
