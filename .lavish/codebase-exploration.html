The most important runtime flow

Herdr owns workspace/process state; Neovim is deliberately a view and controller, not the authority.

Workspace → agent

  1. <leader>fw opens workspaces.

    plugins/herdr/workspaces.lua snapshots authoritative Herdr workspaces and panes.

  2. A Neovim tab binds to one workspace ID.

    Tab-local ID, label, detached and warning state keep UI identity stable.

  3. Selection opens the scoped session picker.

    plugins/sidekick/cwd_picker.lua groups agents, previews terminal output, and manages sessions.

  4. Sidekick attaches through a custom backend.

    herdr_backend.lua registers a Sidekick session implementation that calls the Herdr CLI.

Agent → rendered work

  1. Pi emits assistant and tool updates.

    The local extension discovers Pi’s internal TUI component classes.

  2. Prototype hooks assemble work steps.

    Thinking, title, calls, targets, completion and failure state are coalesced.

  3. A Gruvbox activity tree replaces raw calls.

    Rows preserve chronology and truncate to terminal width.

  4. Stable symbols make reload replacement possible.

    The prototype wrapper keeps original methods and swaps the live controller after /reload.
