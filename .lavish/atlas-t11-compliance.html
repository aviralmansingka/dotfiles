What T11 is supposed to deliver

1 · Landing

Bare atlas opens all recorded Runs with deterministic ordering and an explicit empty state.

2 · Preview

Selection drives the accepted T08 Execution Journal preview.

3 · Drill-down

Enter opens the selected Run’s accepted T07 Expanded Operations Board; return restores browser state.

4 · Contract

Explicit refresh, strict read-only authority, compatible explicit modes, and one semantic ANSI policy across every human surface.

Bottom line by verifier

V01 · Landing browser PARTIAL

The core skeleton exists: bare TTY launch, list, one selection, Journal preview, and empty state. Missing: exact ordering contract, complete population semantics, deterministic reference/minimum goldens, and current explicit-mode compatibility.

V02 · Interaction MOSTLY RED

Clamped j/k and quit exist. Enter drill-down and return are absent. Refresh is backwards: automatic polling exists and r changes panel instead of reloading.

V03 · Authority/compatibility UNPROVEN

The implementation looks read-only, but the full journey has no mutation manifests/traps. Legacy compatibility is broken by the unified CLI migration, and T18’s overlapping PTY verifier is currently red.

V04 · ANSI contract LARGELY MISSING

Journal and aggregate color ingredients exist. The public three-mode contract, forced-color precedence, shared all-surface policy, browser styling, paired captures, and ANSI-preserving screenshot do not.

What should be preserved

  • The unified cmd/atlas binary and bare-TTY browser entry point.
  • The browser’s existing active-Run hierarchy projection and deterministic warning for unrenderable Runs—after the population rule is made explicit.
  • Single selected index, clamped navigation, g/G helpers, TTY alternate-screen integration, and display-cell clipping.
  • Direct reuse of NewJournalModel for the preview.
  • T07/T08 accepted renderer behavior and visual evidence; no new visual prototype is needed.
  • Machine JSON separation from human rendering.

Real implementation remaining

  1. Remove polling and make r perform one explicit reload.
  2. Add Enter-to-T07 Expanded board and a return transition preserving Run and Journal selection.
  3. Settle browser population: recommended active readable Runs plus deterministic diagnostics.
  4. Define supported explicit human-view routes in unified Atlas so compact, Journal, Expanded, Feature, Project, and task drill-down can be compatibility-tested.
  5. Add one public color parser/policy and minimally thread it through every human renderer.
  6. Style browser chrome/list semantically while preserving exact plain text after SGR stripping.
  7. Create T11 V01–V04 verifier assets and migrate the relevant T07/T08 checks to the unified binary.
  8. Restore the overlapping T18.V03 PTY scenario.

Recommended task framing

T11 is not “build a browser from scratch.” It is a convergence task over a partially implemented browser whose current behavior conflicts with two central requirements. Scope it as: preserve the landing skeleton; replace polling with explicit refresh; compose T07/T08; restore a supported human-view compatibility surface; unify ANSI policy; prove authority and deterministic rendering.

Estimated implementation plus verifier convergence: approximately 70k–100k tokens. Safe parallelism: one verifier steward and one product worker after the fresh baseline-red suite is accepted.
