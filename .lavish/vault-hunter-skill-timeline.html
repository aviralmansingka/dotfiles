Landing contract

PR for code, direct push for vault

  • Implementation PR uses existing merge policy and arms auto-merge.
  • The PR opens only after review, refactoring, and verifier additions converge.
  • CI failures remain inside the same Task Run.
  • Required approvals and branch protection are never bypassed.
  • Post-merge checks run before all task-workspace tabs close in Herdr and Neovim.
  • Vault gets two direct commits and pushes—never a PR.

Grill timeline

How the contract sharpened

17 resolved decisions
  1. 01 · Orchestrator

    Reuse Wayfinder, Vault, Grill with Docs, To Spec, and Ponytail instead of rebuilding them.

  2. 02 · Feature terminal

    Feature Run ends with ordered tasks and verifiers—not code.

  3. 03 · Checkbox promotion

    A checkbox-only task is grilled from its own bullets into a durable task note.

  4. 04 · Vault-native spec

    Use To Spec's structure inside the task note; create no duplicate issue.

  5. 05 · Honest red

    Every verifier must fail on the baseline, but current code may already satisfy it.

  6. 06 · Feature-local issues

    Known-ownership decisions live under the owning feature.

  7. 07 · Effort directory

    Each Wayfinder effort keeps its map and tickets together.

  8. 08 · Fog locality

    Unknown ownership starts project-local, then moves intact.

  9. 09 · Stable verifiers

    Task notes retain never-renumbered V01…VNN entries and evidence.

  10. 10 · Refactor Gate

    Refactor only after the first full green; freeze behavior and assertion strength.

  11. 11 · Review Convergence

    Repeat review, Review Refactor, and the active verifier suite; add verifiers when review exposes uncovered behavior.

  12. 12 · PR evidence

    Task notes link implementation PRs. Vault never gets a PR.

  13. 13 · Two checkpoints

    Push in-progress spec/verifiers, then merged final evidence—no per-cycle churn.

  14. 14 · Landing Gate

    Auto-merge obeys existing CI and protections; no-CI repos require mergeable + local green.

  15. 15 · Workspace Cleanup

    After merged-main checks, close every task-workspace tab in Herdr and Neovim; preserve unrelated workspaces and Unbound Tabs.

  16. 16 · PR After Convergence

    Do not open the implementation PR until no relevant review issue remains.

  17. 17 · Goal Timeline

    One continuous timeline shows restartable goal boundaries without numbering them; final evidence stays inside the PR stage.

Confirmed

/goal timeline

One goal reaches checkpoint one; every verifier gets an independent goal; Refactor Gate and Review Convergence get goals; the PR goal captures final evidence; landing always gets a goal; cleanup closes the workspace and pushes the final vault checkpoint.
