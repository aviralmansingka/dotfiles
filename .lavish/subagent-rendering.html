Subagent rendering — color-accurate reference

A faithful reproduction of how pi-interactive-subagents (vendored fork + Herdr surface layer) currently renders in pi, on Gruvbox Material. Every color is the exact hex the extension emits — raw ANSI for the live widget (bypasses theme) or a theme token for the completion boxes. This is the current state we align on before prototyping tree-renderer integration.

The mismatch that motivates this work: the live widget draws its border in a non-theme blue (#4da3ff) and its icons in non-theme yellow/red/gray, while the completion box speaks the theme's token language. Neither uses the tree renderer's glyph vocabulary (▸ ▹ ◆ ◇ ├─ └─ │) at all.

What this is NOT yet

Neither surface uses the tree renderer's vocabulary. The captain's tree renderer (tool-call-renderer.ts) speaks a different glyph language:

 └─ ▸ Thinking                       ▸ muted = done, ▹ accent = working, × error = failed
    ├─ • let me look at the project     • muted bullet, borderMuted connector
    └─ ◆ 2 reads · loaded               ◆ success, ◇ accent pending, × error

The subagent widget is a rounded box with raw-ANSI blue borders; the completion is a flat bg box with ✓/✗. They sit beside, but visually disconnected from, the parent's tree trace. The next step (once this reference is approved) is three prototypes that re-express subagent lifecycle in the tree renderer's ▸ ▹ ◆ ◇ ├─ └─ │ language and theme tokens.
