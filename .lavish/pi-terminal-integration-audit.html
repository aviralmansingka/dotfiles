Shared gaps and Codex blast radius

Below Pi's process boundary.

Fix these with shared terminal tests, not Pi screenshots alone.

A
Sidekick's snapshot scrollback is globally disabled.

herdr_backend.lua sets native_scroll=true for Pi and Codex. Enabling native PTY scrolling bypasses Sidekick's dump-backed, searchable, yankable history.

B
Hidden views can retain takeover ownership.

Sidekick hides the window but keeps its terminal job. A hidden herdr agent attach --takeover can force the next outside client to take over again.

C
Paste state is global across terminal buffers.

The phased bracketed-paste accumulator should be keyed by terminal channel so concurrent Sidekick sessions cannot interleave fragments.

D
Nested Shift-Enter can split into cancel plus Enter.

Ghostty emits ESC CR; Herdr's lone-Escape timeout can flush the Escape before carriage return arrives. Test the complete Ghostty → Neovim → Herdr → Pi route, including Alt chords.

E
Global TERM masks native capabilities.

Shell startup forces TERM=xterm-256color for every boundary. Ghostty/tmux already provide richer terminfo, RGB, OSC52, and extended-key support; compatibility overrides should live only where required.

F
The shared picker parser and activity scrubber are stale.

cwd_picker.lua looks for the old MCP: footer and context shape, missing 🔌 MCP: and 7.7%/1.0M. Its Working scrubber also strips useful Pi and Codex activity feedback.

✓
Codex renderer fallback is simple: leave it alone.

The Pi prompt and prototype patches are Pi-local. Current live Codex output was clean. Narrow shared scroll, paste, attachment, and picker changes instead.

Outside-Neovim and RPC research

Preserve the working transport features; replace the duplicated run loops.

The desired abstraction is one lifecycle reducer with explicit per-surface capabilities.

Telegram · working

A credible remote control surface

Text/captions, allowlisting, mention gating, typing activity, voice/audio transcription, session listing/switching, concise transport prompting, and safe Markdown-like HTML rendering already work.

Telegram · gaps

Delivery is not yet durable

It stops at agent_end instead of authoritative agent_settled, never sends RPC abort on timeout, shares one synchronous session across chats, and persists offsets before processing/delivery.

No steering, photo/image ingress, extension approval flow, or background-subagent completion delivery exists.

WhatsApp · working

A functional text bridge

Allowlisted prefixed text, status/reset, and reply delivery through the local bridge are in place.

WhatsApp · gaps

Behind Telegram's feature floor

It shares the settle/abort/session/dialog/acknowledgement problems and lacks real switch/resume, Markdown, media, typing/progress, and origin/message-ID deduplication. The queried is_from_me field is ignored.

Print / unattended

Semantic output restored; profile work remains

Global APPEND_SYSTEM.md now requests semantic Markdown only, and transcript-scroll is excluded. Other TUI-only extensions still need explicit headless profiles and must not patch private renderer internals during startup.

SSH / tmux

Good foundations, missing E2E proof

50k history, mouse, OSC52, RGB, extended keys, tmux-yank, and reverse-SCP image ingress exist. App mouse capture, dual C-a, guessed callback identity, stale pane environment, and forced TERM remain risks.

Shared RPC reducer requirementsone run, one acknowledgement boundary
Wait for authoritative agent_settled; agent_end can precede a retry.
Send RPC abort on timeout and drain only that run's events.
Resume a real session path/ID; --name only labels a new session.
Isolate state per chat or explicitly declare a shared-session model.
Acknowledge inbound offsets only after durable processing/delivery; use idempotency/outbox.
Sanitize control bytes at the transport boundary.
Model images, progress, steering, approvals, and background completion as capabilities.
Never silently cancel an extension dialog without a transport-visible result.

Target integration

One semantic core, explicit surface adapters.

Equivalent outcomes do not require identical host mechanics.

DIRECT GHOSTTY
Pi owns transcript

Keyboard PageUp/PageDown, explicit copy mode, documented host-selection bypass, clean semantic copy.

HERDR UI
Herdr owns history

Pi receives mouse only at live bottom. Herdr copy mode and 10 MB history own historical interaction.

SIDEKICK / NVIM
Neovim owns history

Live PTY for input; on scroll, materialize herdr agent read into a normal searchable/yankable buffer.

RPC / PRINT
Transport owns render

No terminal ANSI or scroll behavior. Markdown/HTML/plain adapters sanitize, chunk, and deliver semantic content.

Four boundariesdeep core, thin adapters
Semantic core: messages, tools, links, images, approvals, sessions—no ANSI, mouse, clipboard, or $NVIM.
Pi presentation: Markdown/theme and public-width-aware tool components, loaded only in TUI mode.
Surface adapters: history, selection, clipboard, paste/file ingestion, opener, attachment lifecycle.
Explicit profiles: terminal, Herdr child, Sidekick, headless RPC, unattended—no ambient discovery as policy.
