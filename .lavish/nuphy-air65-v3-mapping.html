Nuphy Air65 v3 — Mapping Plan

Crewmate analysis · cross-keyboard parity with the built-in Mac keyboard · shared core + Nuphy-only bonuses · for review before implementation
TL;DR. One mapping scheme that works identically on both keyboards. Shared core (global, both keyboards): CapsLock hold→left_option + tap→esc = left aerospace (pinky, same place on both); right Option = right aerospace (same place on both); Tab hold→Raycast, tap→Tab. Nuphy-only bonuses (device-scoped, won't touch the Mac): Fn hold→right_option (a 2nd right trigger, merged with the firmware Fn layer); red power button→Wispr Flow. AeroSpace stays on alt → all ~80 existing bindings reused unchanged. Muscle memory transfers 1:1 except for the two Nuphy-only extras.

1 · Cross-keyboard parity (the new constraint)

You want the Nuphy mapping "not too different" from the built-in Mac keyboard. The trick: the two boards put Fn on opposite sides, and only the Nuphy has the red button. So we anchor on the keys that exist in the same place on both, and treat the rest as scoped extras.

Shared core — same place on both

  • shared CapsLock → left aerospace (pinky)
  • shared right Option → right aerospace
  • shared Tab hold → Raycast

Applied globally in Karabiner → identical behavior on the MacBook and the Nuphy.

Nuphy-only bonuses

  • nuphy Fn (bottom-right) → 2nd right aerospace trigger
  • nuphy red button → Wispr Flow

Scoped to the Nuphy via Karabiner device_if conditions — the Mac is never disturbed by these.

Mac-only gap to fill

  • mac Wispr has no red button → needs an equivalent combo
  • mac Mac fn/Globe (bottom-left) stays as fn/Globe

Pick a Wispr combo that also works on the Nuphy (e.g. Globe+Tab or Cmd+Ctrl+Space). See §9.

Why Fn can't be a shared trigger. On the Mac, Fn lives bottom-left under your left pinky — pressing it for "right aerospace" would feel wrong, and remapping it kills Globe/fn (emoji picker, dictation, F-key emulation on compact Macs). On the Nuphy it's bottom-right, perfect for a right trigger. So Fn-as-aerospace is a Nuphy-only bonus; the Mac keeps fn/Globe native, and right Option is the consistent right trigger on both.

3 · The hard constraint

AeroSpace binds only cmd · alt · ctrl · shift — not fn (per the AeroSpace guide). The Nuphy Fn layer is firmware-side (the board turns Fn+1 into F1 before macOS sees it). So "share the fn key" is a partition: firmware keeps Fn+number/arrow; AeroSpace gets Fn+letters via Karabiner translating Fn→right_option. This bonus is Nuphy-only.

6 · Sharing the Fn key — the partition

ComboOwnerResultOn Mac?
Fn + 1..0 / - / =firmwareF1..F12n/a (Mac uses row directly)
Fn + arrowsfirmwaremedia / brightness / volumeMac fn+arrows native
Fn + h / j / k / laerospacefocus left/down/up/rightNuphy-only (use right Opt on Mac)
Fn + letters & restaerospaceall alt-* bindings, right handNuphy-only
Verify before committing the Fn merge. Open Karabiner EventViewer, press Fn+1 on the Nuphy:
  • just F1, no Fn flag → merge works; Fn+letter = alt+letter for AeroSpace.
  • Fn flag + F1 → Karabiner turns it into alt+F1, breaking app F-keys. Drop the merge; right Option stays the right trigger.
  • Fn sends nothing → enable "send Fn/Globe to OS" in Nuphy Console; if the board can't emit Fn, drop the merge.
Either way the shared core (CapsLock + right Option + Tab) is unaffected — the Fn merge is strictly additive.

7 · The mapping — Karabiner rules

GLOBAL (both keyboards) — left aerospace: CapsLock, tap = Esc

{
  // applied to every keyboard — identical on Mac and Nuphy
  "from": { "key_code": "caps_lock" },
  "to":   [{ "key_code": "left_option" }],
  "to_if_alone": [{ "key_code": "escape" }],
  "type": "basic"
}

GLOBAL (both keyboards) — Tab hold → Raycast, tap → Tab

{
  "from": { "key_code": "tab" },
  "to":   [{ "key_code": "tab" }],
  "to_if_held_down": [{ "shell_command": "open -a Raycast" }],
  "parameters": { "basic.to_if_held_down_threshold_milliseconds": 200 },
  "type": "basic"
}

NUPHY-ONLY — Fn hold → right_option (2nd right aerospace trigger)

{
  // scoped to the Nuphy via device conditions — Mac fn/Globe is untouched
  // grab vendor_id / product_id from Karabiner → Devices tab
  "from": { "key_code": "fn" },
  "to":   [{ "key_code": "right_option" }],
  "conditions": [{
    "type": "device_if",
    "identifiers": [{ "vendor_id": 9999, "product_id": 9999 }]
  }],
  "type": "basic"
} // only if the §6 EventViewer test passes; else omit and use right Option

NUPHY-ONLY — red power button → Wispr Flow

{
  // VERIFY key_code in EventViewer first: f16 / f17 / f18 / media / power
  "from": { "key_code": "f18" },
  "to":   [{ "shell_command": "open -a 'Wispr Flow'" }],
  "conditions": [{
    "type": "device_if",
    "identifiers": [{ "vendor_id": 9999, "product_id": 9999 }]
  }],
  "type": "basic"
} // if the button is a hardware radio switch (no event), it can't be mapped

MAC-EQUIVALENT — Wispr launch (no red button on the Mac)

{
  // pick ONE combo that works on both keyboards; shown: Globe(fn)+Tab
  // alternative: cmd+ctrl+space, or right_cmd single-tap if you have a spare
  "from": { "key_code": "tab", "modifiers": { "mandatory": ["fn"] } },
  "to":   [{ "shell_command": "open -a 'Wispr Flow'" }],
  "type": "basic"
} // scope with device_unless (Nuphy) if you want the red button to be the only Nuphy trigger

AeroSpace — unchanged

~/.aerospace.toml stays as-is. Because CapsLock, right Option, and (on Nuphy) Fn all emit Option, every alt-* binding is reachable identically on both keyboards.

8 · Largest viable shared mapping — the answer

Largest viable = one alt scheme, a 3-key shared core, 2 Nuphy bonuses, ~80 bindings reused. Shared core (CapsLock·right Option·Tab) is global → identical muscle memory on Mac + Nuphy. Nuphy bonuses (Fn merge·red button) are device-scoped → they add capability without diverging the Mac. Maximal consistency + maximal reuse + zero rewritten AeroSpace bindings. Anything larger would mean inventing bindings you didn't ask for or breaking parity.

9 · Install & verify

  1. brew install --cask karabiner-elements → grant Input Monitoring.
  2. Open Karabiner → Devices, note the Nuphy vendor_id/product_id → fill the conditions placeholders in §7.
  3. EventViewer: press the red power button → note the key_code (f16/f17/f18/media/none).
  4. EventViewer: press Fn+1 on the Nuphy → check for an fn flag (§6 merge test).
  5. If Fn sends nothing: enable "send Fn/Globe to OS" in Nuphy Console; retest.
  6. Drop the rules into ~/.config/karabiner/assets/complex_modifications/nuphy-aerospace.json, enable in Karabiner → Complex Modifications.
  7. aerospace reload-config (no AeroSpace edits needed).
  8. Confirm on both keyboards: CapsLock+h moves focus; right Option+h moves focus; Tab hold opens Raycast; tap Tab types Tab. On Nuphy only: Fn+h moves focus; red button opens Wispr.
