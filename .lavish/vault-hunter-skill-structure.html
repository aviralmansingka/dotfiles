C — Route map

best for: “why do different invocations stop in different places?”

Feature Run

shape the executable plan
  1. Resolve Feature and mark in progress
  2. Read Project → Theme → Feature context
  3. Grill scope and domain language
  4. Produce stable T01…TNN tasks and planned verifiers
  5. STOP before implementation
workspace: Project · Feature

Task Run

deliver one isolated implementation
  1. Mark Task [-] and create Task-named workspace/worktree
  2. Store Task spec + complete verifier ledger
  3. BLOCK for checkpoint-one human evaluation
  4. Run each verifier red → green
  5. Refactor and review until converged
  6. PR, CI, human merge, merged-main checks
  7. Cleanup and checkpoint two
workspace: exact displayed Task name

Issue / Wayfinder

resolve uncertainty into owned decisions
  1. Resolve known or provisional Feature owner
  2. Map effort into stable decision tickets
  3. Move the whole effort when ownership resolves
  4. Promote durable decisions into Feature tasks and verifiers
  5. STOP before implementation
temporary issues, never implementation Tasks
Every route starts the same:
resolve → lifecycle → backlog → commit.
Every worker is visible:
one named Herdr tab, one full Codex pane, one Sidekick session.
Every route ends durably:
accepted evidence is written back by the driver alone.
