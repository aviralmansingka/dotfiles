Placement guards

These are validity conditions, not preferences. A bad placement is replaced before the role starts substantive work.

Accept the dispatch

  • Full interactive Codex session wrapped by Herdr
  • Distinct role tab containing exactly one Codex pane
  • Correct owning route and exact Task or Feature worktree as cwd
  • Distinct agent + Sidekick names using the same feature, run key, and role
  • Returned IDs recorded for monitoring and exact cleanup

Replace the dispatch

  • Background or inherited-pane worker with no full Herdr-visible session
  • Blank root pane plus a split beside the worker
  • Two Task drivers sharing one workspace
  • Task Run in the Feature worktree or any mismatched cwd
  • Hardcoded opaque IDs or identity inferred from a naming pattern
