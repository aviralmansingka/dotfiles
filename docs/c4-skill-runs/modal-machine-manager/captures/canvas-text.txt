 System context: the machine manager is one box. The control plane and humans + mmctl call it; it
 provisions and boots machines through two provider APIs, audits them over SSH and alerts in
 Slack. The machines pull boot artefacts from S3, so L1 opens the box.

 L1 · The machine manager
 L0's box opened one level: its boundary services — private gRPC, webapi, the provider adapter,
 the reconcile loop, SSH + BMC ops and the boot server — sit inside the Machine manager box,
 while the control plane, humans, providers and machines stay outside it.

 L1b · The machine side
 The fleet end of the same system. Machines run the machine-agent, which registers and heartbeats
 into public gRPC inside the manager's box; the River queue uploads audit and bench objects to S3
 and webapi confirms actions in Slack, both outside. The fleet drives these relations.

 L2 · Inside — queue and dispatch
 Inside the box, first slice: requests land on the River queue, which dispatches provision jobs
 to the provider adapter, audit work to SSH + BMC ops and diagnostic events to the janitor
 client; the janitor proposes actions back to webapi. L2b carries the state writes.

 L2b · Inside — the state writes
 Inside the box, second slice: the writes into the Postgres state store — River job rows from the
 queue, machine rows from private gRPC, machine state from public gRPC heartbeats and cluster
 rows from the reconcile loop. Same box, same manager; only the state edges are drawn here.
