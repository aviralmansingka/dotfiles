## Findings and correction candidates

- **F1, high, defect — edge label ownership.** v2 text [41,20,19,3]: the overlay address is nearer the UDP route than its own source-to-host route. A reader can trace both arrows but can misassign the address. The check's `0 ambiguous owners` is not reliable proof here. *Skill-level:* require visual owner review and try a clearer placement/split. *Renderer-level:* route-aware slot placement and proximity-based ambiguity checks should count the competing route.
- **F2, critical, defect — asserted historical identity.** v4 [27,10,30,1] prints `Fios rtr` without `?`, `claimed`, or `hist.`; v3 [19,30,45,1] attaches `(hist.)` to WNC, leaving identity qualification ambiguous. *Skill-level:* carry a clear source qualification on each repeated identity, particularly where split views stand alone. The router border role itself is present, not a missing role.
- **F3, medium, defect — missing qualifier and comparison.** v1 [25,34,33,1] says `no global v6` but does not say ULA-only; v4 includes 1 ISP/1 path and MMR analog but not the 4-ISP/2-MMR comparison. *Skill-level:* audit every source qualifier and comparison against rendered labels rather than treating a shorthand or ledger entry as proof. Rendering constraints need measured evidence before claiming a yield.
- **F4, medium, defect — group-family drift.** v2 `wifi` ANSI [24,33,13,4] is magenta; v3 `wifi` ANSI [43,21,8,4] is orange. *Renderer-level:* use name-stable family assignment independent of the set of other group names while avoiding collisions; *skill-level:* check shared names across views. Absence of enclosing group geometry is correct.
- **F5, medium, defect — incomplete family recipe.** The chosen family and stated secondary rules fit the source; the visible coverage, not the classification, fails the identity-map recipe because of F1–F3.
- **F6, high, evidence gap — one probe's binary binding.** `probe-multiline-frames` in `attempts-log.jsonl` records null binary path and hash for the `env COLUMNS=77 ... /tmp/.../rataflow-view` command. Probe output and spec hashes are recorded, and today's binary matches frozen metadata, but the execution-time binary hash is not established by that record. `attempts.json` additionally mistypes the rejected v1-a1 digest; its preserved bytes match the actual log. *Harness-level:* bind the executable through shell/environment wrappers and verify the attempt index against preserved bytes. This is an evidence gap, not proof the probe used a different binary.
