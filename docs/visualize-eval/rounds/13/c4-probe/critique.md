## Source relationship and C4 judgment

All 23 required endpoint pairs are present in the spec and coverage map. This is not equivalent to 23 readable, complete relation meanings. The `audit / verify reimage` relation is thinned to `audit`, and `boot.ipxe + S3 args` loses the argument qualifier; both are genuine semantic losses. `create/term/repair`, `reinstall/reprov`, `register+beat`, and `diag uploads` are abbreviated; context helps a reader infer some, but the full expansions are not all explicitly keyed on the canvas. `BM` is not keyed on the canvas. A ledger discloses the full original forms but does not restore them to the visualization. On reconsidering the whole-canvas frame after the blind record, the controls cover the queue's left border but its outgoing routes start at its unobscured right side. The blind record's claim that queue outputs are obscured was too strong; it remains unchanged as the original observation. The two boot directions, janitor proposals, separate diagnostics and machine image retrieval are visibly distinct.

Context-level aggregates are legitimate C4 zoom abstractions, not extra independent source facts, provided they expand into the recorded L2 edges. L1 is recognizably one manager system with actors and external systems, but merges a human and CLI and omits explicit actor/system typing. L2 is split into two related views with repeated nodes and no shared visible parent level band. It is plausible as a set of container-like diagrams, but a reader cannot reliably tell manager-owned containers from external systems purely from label/hue; groups have no key or visible boundary. The machine-agent's inside/outside designation is an inference from host and heartbeat relationships, not an independently documented deployment boundary. No L3 internals or L4 code are asserted, appropriately: the source does not establish them.
