### Fixed constraints

- **Separate `core -> cache` and `web -> cache`.** They are two distinct labelled edges with
  different sources, never merged or reversed: `25 GbE` in view 02 and `session` in view 03.
  They sit in two views because the frozen renderer fails when both attach to Redis in one
  pane (see attempts `fanin-4node`) — it side-attaches `web -> cache` and drops its arrowhead.
- **Speeds visible, motion not a measurement.** `1 GbE`, `10 GbE` and `25 GbE` appear as text
  labels. All seven edges carry the same `flow: 0.2` (about 2 cells/second, dots ≥ 7 cells
  apart), so a dot shows direction of traffic and its speed measures nothing. The historical
  wish to let dot speed encode link speed is therefore not implemented; the round's constraint
  overrides it.
- **Slow, sparse motion.** Uniform `0.2`; four timestamped frames per view show the dots
  advancing about 5–6 cells every 2.5 s.

header. Every compact alternative that fits (5 nodes, 4–5 edges) was rendered and rejected for

- `attempts/link-path-01-auto-4edge/` — Web tier and Redis shared one layer; both core edges
  entered side handles with no arrowhead.

  arrowhead, and the `session` stem branches off that same cell (false branch).
- `attempts/fanout-3node/`, `attempts/fanin-4node/`, `attempts/app-chain-span/`,

- `attempts/link-path-03-explicit5/`, `attempts/link-path-02b-explicit4/` — dropped labels
  (2 labels `had no free slot`) and zigzag stems.

The pattern: this frozen renderer draws a clean, arrowheaded forward edge only when the target
box sits essentially below the source. Two boxes in one layer, or a sideways offset target,
produces a side attachment with the arrowhead overwritten by the border. So each view is a
single vertical chain, and coverage is explicit in `generation.json`.

## Decisions worth knowing

- **`tb`, not `lr`.** The 5-layer request path in `lr` measures `92x8` — wider than the 77-column
  pane — and the 3-node views measure `53x8` with one dropped label. `tb` fits every view.
- **Node label `Redis cache`.** Faithful to the source (node `cache` = Redis, in the cache tier)
  and it widens the box enough for the `session` label to get a free cell. With plain `Redis`
  the 14-column layout dropped that label (`--check`: `1 edge label(s) had no free slot`).
- **`fill` appears twice**, in 02 and 03, same direction, same label. A 2-node view cannot place
  a single edge label with this renderer, so each cache view carries the `cache -> db` edge.
  Declared duplication, nothing else is duplicated.
