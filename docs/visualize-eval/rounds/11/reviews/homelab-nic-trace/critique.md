## Findings

1. **Defect — critical, semantic fidelity:** `source.md` “What the probes found” and “Relationship facts” explicitly require the backup route's metric 600. The wifi-to-router edge in pinned v1 [52,28,25,1] says `metric failover, not ECMP`. The value is not elsewhere on any final graph. The generator's `known_defects` claim that the value appears in the wifi node or edge is contradicted by the final capture and spec. The endpoint and direction are still clear, but the required edge's numeric label meaning fails. Clean `--check` does not test source semantics.
2. **Defect — medium, semantic fidelity:** The source identifies the host's `~/rack-bench` latest runs as Oct 11. The host labels in v1 [11,16,56,1] and v3 [12,30,56,1] include the path but no date. This loses the time qualifier; no date is recoverable from the graphs.
3. **Evidence gap — high, workflow:** SHA-256 of `docs/visualize-eval/cases.json` is `e69179e59a3d36985cd7e8692b319b566701f88caef385c9cbde76d060c92d05`, while frozen `metadata.json` records `e69179e59a3d36985cd7e8692b319b566701f88caef385c9cbde76d060c92d05`. The source, expected, variants, skill, rubric and frozen binary do match their metadata hashes. Do not silently substitute the current dataset hash for the frozen identity.
4. **Evidence gap — high, workflow:** The attempts log actually contains 11 entries, including the failed 127 invocation and rerun, not 10. All 11 recorded stdout/stderr pairs match their recorded hashes. However, four old spec hashes point at files since overwritten (`v1-lan-a1`, `v1-lan-a2`, `v2-wan-a1`, `v3-virt-a1`); their raw stdout is check output, not preserved JSON spec bytes as `attempts.json` claims for v3-a1. The v1-a2 hash in `attempts.json` also differs from the log. Claimed rejected-draft 77×47 dump files are not in the bundle and no dump commands are in the log. Thus the rejected attempts' exact content and visual overflows are not independently reproducible from the preserved record even though all three `validate-v*.txt` files say records complete.

`192.168.1.0/24` is not written literally: v1 [15,30,22,1] says `LAN /24`, and v1 [17,24,19,1] supplies `192.168.1.197`; the network prefix is uniquely recoverable by applying /24. This is an abbreviation, not an additional missing fact here, though a literal address would be less demanding. `v6 ULA-only` on the host means no global v6 and supports the no-v6-internet bench answer when combined with the IPv4 egress trace; NAT and `no CIR` are explicit in v2. Both router labels visibly include `border` and `hist.`; v2 also has `WNC OUI`, and the ONT says `(hist.)`. The different router labels are documented and complementary. The source cautions that traceroute hops are historical; the graph marks the ONT and router but does not carry a global historical caption on later WAN hops. Read the entire trace as the historical observation supplied by the case, not verified physical topology; this is a qualification clarity concern, not an extra false topology finding.

The generator cites 372×9 LR and 78×97 TB merged probes plus 233×6 WAN LR as reasons for the view/orientation choices; the corresponding check output is preserved. This supports the stated rationale but does not prove every possible merged `label_slot` design impossible. The softer category rule asks for a reasoned deviation, not that this example be exhausted. The `minlen: 3` overlay corridor keeps the UDP route readable and avoids the stated wide middle rank; the missing exact rejected spec means the specific rejected geometry remains an evidence gap, not a proven capability blocker.
