# Herdr Attachment Leases: Phase 1 V2 Capability Plan Contract

V2 freezes the inspectable Capability Plan that projects V0 authority through a V1 lease snapshot onto one declared
surface. It defines what adapters will consume later without implementing the Herdr command or changing Sidekick.

- Status: `frozen`
- Lifecycle contract: [`contracts/herdr-attachment-leases-v1.json`](contracts/herdr-attachment-leases-v1.json)
- Machine-readable plan contract: [`contracts/herdr-attachment-leases-v2.json`](contracts/herdr-attachment-leases-v2.json)
- Plan fixtures: [`../scripts/fixtures/herdr-attachment-leases-v2/plans.json`](../scripts/fixtures/herdr-attachment-leases-v2/plans.json)

## Inspect command

The future human command is `herdr attachment plan <attachment-id>`. Machine consumers use
`herdr attachment plan <attachment-id> --format json`, whose successful JSON envelope contains
`result.capability_plan`.

The stable errors are `attachment_not_found`, `surface_detached`, and `plan_unavailable`. Inspection is read-only. It
does not request, renew, release, or transfer the Attachment Lease.

## Plan shape

A `herdr.capability-plan` major-version `1` document has these required fields:

- `schema`, `version`, and monotonically increasing `revision`;
- the exact `agent_session` identity and `surface_attachment` identity/kind;
- one V1 `lease` snapshot, including the surface role and whether it is the pending requester;
- all eleven V0 `capabilities`, each appearing once with its canonical authority, surface provider, and mode;
- explicit `compatibility` behavior.

The resolution inputs are the V0 authority contract, V1 lease snapshot, surface declaration, and agent provider. A plan
is a projection of those authorities; it never becomes an independent source of session or lease truth.

## Surface profiles

| Capability | Neovim provider | Terminal provider |
| --- | --- | --- |
| Historical view | Sidekick buffer | Herdr copy mode |
| Search, selection, and copy | Neovim | Herdr / host terminal |
| Live input and interactive mouse router | Sidekick adapter | Herdr terminal adapter |
| Link and file opening | Neovim navigation | host terminal |
| Paste and file ingestion | Neovim normalization | terminal input normalization |

Session identity, transcript storage, and seen/unseen reporting remain provided by Herdr. Pi or Codex provides the same
running conversation and model state; the matching Agent TUI provides live rendering.

## Role projection

- A `lease_holder` plan sets `live_input` and `interactive_mouse_routing` to `allow`.
- Every `observer` plan sets both to `deny`, including an unheld surface or a pending requester.
- A transfer request does not change the current Lease Holder's plan until approval, release, or expiry promotes the
  requester.
- Native history, search/copy, opener, paste, and focus modes are available to attached Observers without granting live
  authority.

## Compatibility behavior

| Condition | Required behavior |
| --- | --- |
| Unknown field under the same major version | `ignore` |
| Missing required field | `reject` |
| Unsupported major version | `reject` |
| Unknown surface profile | `reject before attachment` |
| Missing plan | `fail closed for live input and interactive mouse; never fall back to takeover` |
| Stale revision | `refresh before live input or interactive mouse` |
| Current Herdr 0.8 and Sidekick | `unchanged in Phase 1; does not emit or consume Capability Plans` |

The compatibility rules describe the future contract boundary. Phase 1 does not retrofit them into the installed
runtime. In particular, the current unconditional `--takeover` remains present only as the unchanged baseline—not as a
fallback allowed by the Capability Plan contract.

## Invariants

1. Every attached surface receives one complete plan for one Agent Session and one Surface Attachment.
2. Each V0 capability appears exactly once with its V0 canonical authority.
3. Only the Lease Holder plan allows live input and interactive mouse routing.
4. A pending requester remains an Observer until promotion.
5. History, search, copy, open, paste, and focus providers are surface-native and do not grant lease authority.
6. A plan is a revisioned snapshot and must be refreshed after lease state changes.
7. Missing, stale, malformed, or unsupported plans fail closed for live authority.
